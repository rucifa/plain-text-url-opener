# Plain Text URL Opener v1.0.9 — Post-release Integration Acceptance

Date: 2026-09-28  
Production commit under test: `96956264e79de2d815b3f4fea6c45eb6b6756039`  
Regression Fixture: **v1.2 / 166 cases (unchanged)**

## Purpose

v1.0.9 changed icon encoding / publication metadata only; parser and runtime behavior were not intentionally changed from the accepted v1.0.6 runtime. This post-release audit therefore focuses on integration edges that were not the primary target of the earlier parser acceptance suite: SPA DOM replacement, iframe isolation, Shadow DOM behavior, editable / interactive controls, reinjection, security-boundary spot checks, and bounded interaction cost.

The audit did **not** change Fixture expectations and did **not** relax any security boundary to make a test pass.

## Test environment

Controlled browser tests ran in GitHub Actions on Ubuntu 24.04 using Playwright 1.55.0 with:

- Chromium 140.0.7339.16 (Playwright build 1187)
- Firefox 141.0 (Playwright build 1490)

Userscript-manager-specific iframe injection policy was not simulated. For iframe tests, the v1.0.9 runtime was injected directly into the relevant document so the audit could verify behavior and isolation **when the script is present in that frame**.

## Result summary

**Verdict: PASS — no runtime patch recommended.**

No security regression, unbounded background work, duplicate-listener problem, or editable-control auto-open was found. No v1.0.10 runtime release is justified by this audit.

### Harness corrections

Two earlier exploratory runs produced misleading failures and are **not product failures**:

1. An early observer probe counted a MutationObserver created by the browser-testing harness itself. The audit was corrected to use production-source checks and before/after deltas.
2. A Firefox native-click probe calculated coordinates for off-screen Fixture rows without scrolling them into view. The browser therefore received no dblclick event for those rows. After `scrollIntoView()` was added and actual dblclick receipt was required, all target Fixture cases passed.

These corrections are recorded so the exploratory failures are not mistaken for regressions later.

## Shadow DOM

Shadow DOM behavior is browser-dependent and is treated as a **Limitation / non-guaranteed integration boundary**, not as a reason to broaden DOM traversal.

Native double-click observations:

| Scenario | Chromium | Firefox |
|---|---|---|
| Plain-text URL in open Shadow DOM | not opened | opened |
| Plain-text URL in closed Shadow DOM | not opened | opened |
| `contenteditable` inside open Shadow DOM | ignored / PASS | ignored / PASS |

Firefox can expose enough composed-event / Selection information for the current document-level handler to recognize some Shadow DOM text, while Chromium does not do so through the same native path. The script does not explicitly traverse closed shadow roots.

**Decision:** document this browser-dependent behavior and keep the current lightweight architecture. Do not add Shadow-root discovery, MutationObservers, or background scanning merely to force cross-browser parity.
