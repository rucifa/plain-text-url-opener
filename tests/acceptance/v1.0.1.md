## Reproducible issue fixed

On an existing real `<a href>` element, the initial ignore check relied on `PointerEvent.target` / `MouseEvent.target`. Under a target-vs-caret/selection mismatch, the event target can be outside the anchor while the caret or Selection resolves to a TextNode inside the anchor.

This allowed Plain Text URL Opener to process text that is already part of a native hyperlink.

Representative case:

```html
<a href="http://www.mozilla.gr.jp/party5.0/">Mozilla.Party.jp 5.0</a>
```

Reproduction used for regression:

- event target: outer container
- caret / Selection TextNode: inside the `<a href>`
- v1.0.0 result: incorrectly detected/opened `https://mozilla.party.jp/`
- expected: ignore the native link completely

## Fix scope

No parser change was made.

Two narrow containment checks were added:

1. After hover caret resolution, verify the resolved TextNode's parent is not inside an ignored element.
2. After double-click Selection resolution, verify the selected TextNode's parent is not inside an ignored element.

The existing `isIgnoredElement()` policy remains authoritative, including `<a href>`, form controls, `[role="textbox"]`, and editable content.

## Reverse regression validation

The same new regression tests were run against both versions:

- **v1.0.0:** 41 / 43 passed; the two new existing-link mismatch tests failed.
- **v1.0.1:** 43 / 43 passed in the same focused harness.

The two v1.0.0 failures were:

- existing-anchor hover mismatch leaked `Plain Text URL → https://mozilla.party.jp/`
- existing-anchor double-click mismatch opened `https://mozilla.party.jp/`

Both are fixed in v1.0.1.
