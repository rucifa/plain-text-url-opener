# Plain Text URL Opener v1.0.3 — Acceptance Report

## Decision

**GO — v1.0.3 Stable**

This patch is limited to reproducible correctness/security regressions discovered by the canonical Regression Fixture v1. No new product feature or settings UI was added.

## Fixed regressions

### 1. Explicit CJK IDN hostname labels were truncated

v1.0.2 incorrectly treated CJK starting a later hostname label as adjacent prose.

Fixed examples:

- `https://www.例え.jp/` → `https://www.xn--r8jz45g.jp/`
- `https://example.みんな/` → `https://example.xn--q9jyb4c/`
- `https://www.例え.jp/path中文` → `https://www.xn--r8jz45g.jp/path`

Existing adjacency behavior is preserved:

- `https://example.com中文` → `https://example.com/`
- `https://example.com/test中文` → `https://example.com/test`

Conservative scheme-less behavior is unchanged; e.g. `www.例え.jp` remains unsupported.

### 2. Unsupported outer schemes could leak a nested HTTP(S) candidate

v1.0.2 could extract an inner HTTP(S) URL from an unsupported token such as:

- `blob:https://example.com/1234`
- `data:text/html,https://example.com/x`
- `javascript:https://example.com/x`
- `file://https://example.com/x`
- `ftp://https://example.com/x`
- `mailto:https://example.com/x`

v1.0.3 rejects those nested candidates. Ordinary labels such as `link:https://example.com/x` remain supported.

### 3. Cross-TextNode split URLs could open a truncated prefix

Cross-TextNode URL reconstruction remains intentionally unsupported. However, v1.0.2 could open an incorrect prefix:

- `http://www.<em>mozilla</em>.org/` → incorrectly `http://www/`
- `https://example.<span>com</span>/path` → incorrectly `https://example/`

v1.0.3 does not rebuild the full URL, but suppresses these known truncated-prefix cases instead of opening the wrong target.

The final implementation is intentionally narrow: it only detects the reproducible trailing-period split pattern and does not introduce generalized DOM traversal or layout scanning.

## Regression results

### Final v1.0.3 artifact

- Static / architecture checks: **14 / 14 PASS**
- Targeted parser + security + fixture regressions: **82 / 82 PASS**
- Chromium interaction / lifecycle suite: **34 / 34 PASS**
- Ordinary differential fuzz: **10,000 cases, 0 unexpected differences**

### Negative-control comparison

Running the same new targeted suite against v1.0.2 produced:

- **67 PASS / 15 FAIL**

This confirms the added tests reproduce real v1.0.2 behavior rather than merely matching the new implementation.

## Performance

Chromium measurements for the final v1.0.3 artifact:

| Case | Median | p95 |
|---|---:|---:|
| Normal ~8 KB text | ~2.1 ms | ~3.1 ms |
| Dotted pathological ~8 KB | ~3.1 ms | ~3.6 ms |
| ~8 KB excess closing parentheses | ~0.8 ms | ~1.3 ms |
| Explicit ~7 KB URL | ~0.2 ms | ~0.3 ms |
| Huge spaced TextNode | ~2.1 ms | ~3.1 ms |
| Huge contained explicit URL | ~0.2 ms | ~0.4 ms |

CJK-IDN stress check after optimizing the first patch attempt:

| Case | v1.0.2 median | v1.0.3 median |
|---|---:|---:|
| ~8 KB CJK authority | ~23.8 ms | ~24.4 ms |
| ~1000 CJK IDN labels | ~27.9 ms | ~27.7 ms |
| ~8 KB CJK path | ~2.9 ms | ~2.5 ms |

An intermediate implementation briefly showed ~165 ms on the long CJK-authority case; it was rejected and rewritten as a linear scan before release.

## Scope / non-goals preserved

- No MutationObserver
- No setInterval / requestAnimationFrame scanning loop
- No full-page rescanning
- No DOM linkification
- No settings UI
- `@grant none`
- HTTP(S)-only final navigation
- Cross-TextNode URL reconstruction still unsupported
- Relative paths still disabled
- Bare IPv4 still unsupported
- Conservative scheme-less IDN behavior preserved
