## Classification and scope

The accepted v1.0.11 changes are deliberately narrow:

1. **Performance bug / boundedness hardening** — Cross-TextNode truncated-prefix safety could scan the entire remaining TextNode and could materialize a full sibling element `textContent` before applying the 256-character context budget.
2. **LOW security hardening** — if assigning `opened.opener = null` threw, the previous fallback could still navigate the popup instead of failing closed.

No URL-recognition Spec change is part of v1.0.11.

During the independent audit, mixed ASCII + CJK path/query/fragment text was initially considered a possible parser bug. A candidate parser change was intentionally tested against the unchanged Fixture and failed the existing `path-adjacent` specification. The candidate change and its provisional new cases were discarded. Existing Fixture expectations were not modified. This was reclassified as an existing **Limitation / Spec ambiguity**, not an implementation regression to fix silently.

## Implementation changes

### Bounded DOM-split safety

- same-node trailing inspection uses a bounded probe instead of slicing/scanning the complete remaining TextNode;
- sibling context keeps at most **256 text characters**;
- sibling traversal visits at most **512 DOM nodes**;
- exhausting that node budget fails closed;
- oversized ambiguous same-node context also fails closed;
- Cross-TextNode reconstruction remains intentionally unsupported.

### Popup isolation

- `opened.opener = null` is now an explicit security gate;
- if isolation throws, the blank popup is closed when possible and navigation returns `false`;
- normal `location.replace()` with `location.href` navigation fallback is preserved after successful opener isolation.
